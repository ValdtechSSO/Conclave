# System overview

Conclave is a local .NET CLI with stable commands (`plan`, `show`, `doctor`, `prune`). The CLI delegates application behavior to feature slices in orchestration. Core contains contracts only; adapters isolate provider-specific behavior; repository services own Git snapshots and worktrees; validation owns deterministic gates; infrastructure owns processes, persistence, configuration, budgets, and retention.

The project split follows the implementation plan. Inside each project, new behavior remains feature-first. Dependencies point inward toward `Conclave.Core`; provider, Git, filesystem, and process details do not enter Core.

The JSON files under `src/Conclave.Orchestration/Features/Plan/Schemas/` remain authoritative and are colocated with the planning feature that owns them. Provider adapters may derive an invocation-only representation for a provider's supported JSON Schema dialect (for example, Claude's draft-agnostic form or OpenAI's all-properties-required strict form), but validation always uses the unchanged authoritative schema.

Before provider execution, the repository layer validates a set of recommended repository-relative starting paths against the retained snapshot. Conclave sends only those paths, never the files' contents, in the prompt. Providers use read-only tools inside their isolated worktrees, begin at the recommended paths, and may follow direct dependencies, consumers, contracts, tests, or concrete evidence gaps elsewhere in the snapshot. They must keep exploration focused and cannot mutate files, Git state, or remotes.

Cross-review and synthesis inputs are materialized as anonymous JSON files under the isolated worktree's `.conclave-input`; they are not duplicated inline in prompts. Providers read only the artifacts needed for their phase.

After cross-review, orchestration assigns stable anonymous IDs to every unresolved disagreement and materializes a disagreement catalog for synthesis. Final plans preserve those IDs exactly once while remaining free to paraphrase or group related disagreements; deterministic validation checks ID coverage instead of brittle text equality.

The CLI persists every progress event as JSONL and may mirror it to stderr as text or JSONL. This gives terminals, IDE agents, and other callers a live stream without contaminating machine-readable stdout. The provider boundary translates public process and stream events into content-free activity codes; reasoning and generated response text are never forwarded into progress. Provider adapters apply hard native controls where available (for example Claude USD limits), while orchestration records every attempt and enforces reported budgets before any subsequent call. Token and cumulative provider-duration limits are isolated per provider so inexpensive or slower models can receive independent allowances; run-wide limits cover elapsed duration, call count, and reported cost without pooling provider tokens.

The logical OpenAI and DeepSeek providers share the Codex CLI process adapter but remain isolated participants with distinct credentials, model selections, and audit identities. DeepSeek is configured per invocation as a custom Responses API provider; no user Codex configuration or secret file is modified.

Structured output parsing is strict-first. If exact parsing fails, Conclave may apply only a conservative local syntax repair for an unambiguous missing comma between complete JSON values on adjacent lines. The original output and repaired JSON are both retained, a public repair event and run warning are emitted, and the repaired artifact must still pass the authoritative schema plus every structural and evidence validation. Local repair never triggers a paid provider call.

Repository evidence matching is also strict-first. An exact ordinal source match is preferred. For C# `string_literal` evidence only, validation may deterministically expand a complete `{nameof(Identifier)}` interpolation to its compile-time identifier before matching. Runtime expressions, fuzzy text, case folding, and approximate symbols remain invalid.

Validation distinguishes essential failures from recoverable provider formatting. Unsafe evidence paths, a repository claim whose cited files are all absent, ambiguous duplicate artifact IDs, unsafe/conflicting implementation targets, missing executable steps, and omitted cataloged disagreements remain blocking. A symbol that cannot be matched in an existing file is retained as not deterministically verifiable and follows the configured evidence policy; one verified reference is sufficient when other references are redundant and bad. Redundant unknown support IDs, blank test entries, review alias spelling, duplicate/unknown disagreement references, omitted nonessential collections, and assumptions missing from `openQuestions` are normalized locally, retained as warnings, and never trigger another provider call.
